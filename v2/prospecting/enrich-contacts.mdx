---
title: "Enrich prospecting contacts with full contact data"
sidebarTitle: "Enrich Contacts"
description: "Turn contact IDs from a prospecting search into full records — verified emails, phone numbers, job title, company details, and location data."
---

`POST https://api.lusha.com/prospecting/contact/enrich` is step 3 of the 3-step prospecting flow. You pass the `requestId` and `contactId` values returned by [Search Contacts](/v2/prospecting/search-contacts) and receive back complete contact records with verified emails, phone numbers, job details, and company information. Credits are charged at this step for each contact successfully enriched.

## Request body

Send a JSON body with the `requestId` from your search response and an array of `contactIds` to enrich. You can enrich up to 100 contacts per request.

```json
{
  "requestId": "b6effae6-35b8-493d-91aa-7d3b1b7c7dc7",
  "contactIds": ["06de9b18-516d-5512-5cb5-6ec5pb215776"]
}
```

### Request fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `requestId` | string | Yes | The `requestId` returned by `/prospecting/contact/search` for the same session |
| `contactIds` | string[] | Yes | `contactId` values from the search results. Minimum 1, maximum 100 |
| `revealEmails` | boolean | No | Return only email addresses. Requires the Unified Credits plan |
| `revealPhones` | boolean | No | Return only phone numbers. Requires the Unified Credits plan |

## Unified Credits plan requirement

<Warning>
  `revealEmails` and `revealPhones` are only available to customers on the **Unified Credits** pricing plan. Passing either parameter on another plan returns a `403` error. When you omit both parameters, the API returns all available contact data — including emails and phones.
</Warning>

```json
{
  "requestId": "b6effae6-35b8-493d-91aa-7d3b1b7c7dc7",
  "contactIds": ["06de9b18-516d-5512-5cb5-6ec5pb215776"],
  "revealEmails": true,
  "revealPhones": true
}
```

## Example request

<CodeGroup>

```bash cURL
curl --request POST \
  --url https://api.lusha.com/prospecting/contact/enrich \
  --header 'api_key: YOUR_API_KEY' \
  --header 'Content-Type: application/json' \
  --data '{
    "requestId": "b6effae6-35b8-493d-91aa-7d3b1b7c7dc7",
    "contactIds": ["37b4c536-eaec-11ef-ad4b-a75f8e9e1484"]
  }'
```

```json Request body
{
  "requestId": "b6effae6-35b8-493d-91aa-7d3b1b7c7dc7",
  "contactIds": ["37b4c536-eaec-11ef-ad4b-a75f8e9e1484"]
}
```

</CodeGroup>

### Response fields

| Field | Description |
|-------|-------------|
| `id` | The `contactId` you submitted |
| `isSuccess` | Whether enrichment succeeded for this contact |
| `data.firstName` / `lastName` / `fullName` | Contact's name |
| `data.jobTitle` | Current job title |
| `data.departments` / `seniority` | Department and seniority level details |
| `data.location` | City, state, country, and continent |
| `data.emailAddresses` | Array of email objects with type, confidence, and update date |
| `data.phoneNumbers` | Array of phone objects with type and DNC status |
| `data.companyId` / `companyName` | Current employer identifier and name |
| `data.company` | Additional firmographics: revenue range, funding, intent, industry, technologies |

See the [full API reference](/v2/api-reference/prospecting/enrich-contacts) for the complete response schema.

<Tip>
  Enrich in batches of up to 100 IDs per request. If your search returned more results than you want to enrich immediately, store the `requestId` and `contactId` values and enrich them on demand as contacts are needed in your CRM.
</Tip>
