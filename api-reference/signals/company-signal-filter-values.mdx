Returns the valid values for one company signal filter type. Call [Get Company Signal Filters](/api-reference/signals/company-signal-filters) first if you need to discover which `filterType` values exist and whether each requires a `query`.

## Endpoint

```
GET https://api.lusha.com/v3/companies/signals/filters/{filterType}
```

**Authentication:** API key (`ApiKeyAuth`)

---

## Path parameters

<ParamField path="filterType" type="string" required>
  The filter type to retrieve values for.

  Allowed values: `newsEventTypes`, `hiringByDepartments`, `hiringByLocations`, `intentCategories`, `intentTopics`
</ParamField>

## Query parameters

<ParamField query="query" type="string">
  Text to match values against. 2–256 characters.

  | Filter type | Query required? |
  |---|---|
  | `newsEventTypes` | No |
  | `hiringByDepartments` | No |
  | `hiringByLocations` | Yes (2–256 chars) |
  | `intentCategories` | No - passing `query` returns `400` |
  | `intentTopics` | Yes (2–256 chars) |
</ParamField>

<Warning>
  `hiringByLocations` and `intentTopics` require `query` - omitting it returns a `400`. `newsEventTypes` and `hiringByDepartments` return their full value list whether or not you pass a `query`.
</Warning>

<Info>
  `intentTopics` searches the full intent topic catalog (about 18,000 topics) - not the topics selected in your dashboard. It returns up to 50 matching topic names as plain strings, and an empty `values` list when nothing matches. Pass the names as `filters.include.intentTopics` on [Company Signals](/api-reference/signals/company-signals). This call is free.
</Info>

## Example requests

<CodeGroup>

```bash newsEventTypes
curl --request GET \
  --url https://api.lusha.com/v3/companies/signals/filters/newsEventTypes \
  --header 'api_key: YOUR_API_KEY'
```

```bash hiringByDepartments
curl --request GET \
  --url https://api.lusha.com/v3/companies/signals/filters/hiringByDepartments \
  --header 'api_key: YOUR_API_KEY'
```

```bash hiringByLocations
curl --request GET \
  --url 'https://api.lusha.com/v3/companies/signals/filters/hiringByLocations?query=California' \
  --header 'api_key: YOUR_API_KEY'
```

```bash intentTopics
curl --request GET \
  --url 'https://api.lusha.com/v3/companies/signals/filters/intentTopics?query=cloud%20hr' \
  --header 'api_key: YOUR_API_KEY'
```

</CodeGroup>

## Response

### 200 - Success

<ResponseField name="values" type="any">
  The matching values for the requested `filterType`. Nullable - returns `null` when nothing matches.
</ResponseField>

<Info>
  The API's `FilterValuesResponse` schema leaves `values` open-ended so it can represent different filter shapes. Treat the response as authoritative and read it directly rather than hardcoding a shape - the example below is illustrative.
</Info>

<ResponseExample>

```json 200 (newsEventTypes)
{
  "values": [
    "Funding Round",
    "IPO",
    "Executive Hire",
    "Product Launch"
  ]
}
```

```json 200 (hiringByLocations?query=California)
{
  "values": [
    "United States > California"
  ]
}
```

```json 200 (intentTopics?query=cloud hr)
{
  "values": [
    "Cloud HR Platform"
  ]
}
```

</ResponseExample>

## Error codes

| Status | Meaning |
|--------|---------|
| `400` | Bad request - `filterType` is invalid, or `query` is missing/too short/too long for `hiringByLocations` or `intentTopics`. |
| `401` | Unauthorized - your API key is missing or invalid. |
| `403` | Forbidden - account inactive or V3 access not enabled. |
