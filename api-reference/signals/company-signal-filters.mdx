This is the discovery endpoint for company signal filters. Call it first to learn which filter types exist and whether each one needs a `query` string - then call [Get Company Signal Filter Values](/api-reference/signals/company-signal-filter-values) with a specific `filterType` to retrieve the actual values.

## Endpoint

```
GET https://api.lusha.com/v3/companies/signals/filters
```

**Authentication:** API key (`ApiKeyAuth`)

This endpoint has no parameters.

---

## Example request

```bash cURL
curl --request GET \
  --url https://api.lusha.com/v3/companies/signals/filters \
  --header 'api_key: YOUR_API_KEY'
```

---

## Response

### 200 - Success

<ResponseField name="availableFilters" type="object[]">
  One entry per available filter type.

  <Expandable title="properties">
    <ResponseField name="filterType" type="string">
      The filter type identifier. Pass this value as the `filterType` path parameter on [Get Company Signal Filter Values](/api-reference/signals/company-signal-filter-values).
    </ResponseField>
    <ResponseField name="requiresQuery" type="boolean">
      Whether you must supply a `query` parameter when fetching values for this filter type.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseExample>

```json 200
{
  "availableFilters": [
    { "filterType": "newsEventTypes", "requiresQuery": false },
    { "filterType": "hiringByDepartments", "requiresQuery": false },
    { "filterType": "hiringByLocations", "requiresQuery": true }
  ]
}
```

</ResponseExample>

<Info>
  `hiringByLocations` requires a `query` of 2–256 characters - it's a text-search filter rather than a fixed list. `newsEventTypes` and `hiringByDepartments` return their full value list without a query.
</Info>
