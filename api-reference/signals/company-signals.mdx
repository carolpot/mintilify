Use this endpoint when you already have Lusha company IDs and want their signal activity - hiring surges, headcount changes, web traffic and IT spend shifts, and categorized news - in one call. Pass up to 100 `ids` and the `signalTypes` you want back; there is no separate "search" step in V3 - one call returns all matched signal data for the IDs you send.

<Info>
  Don't have Lusha company IDs yet? Resolve companies first with [Enrich Companies](/enrichment/enrich-companies) or [Search & Enrich Companies](/enrichment/search-and-enrich-companies), then pass the returned `id` values here.
</Info>

## Endpoint

```
POST https://api.lusha.com/v3/companies/signals
```

**Authentication:** API key (`ApiKeyAuth`)

---

## Request body

<ParamField body="ids" type="string[]" required>
  Lusha company IDs to retrieve signals for. 1–100 items per request.

  Example: `["16303253"]`
</ParamField>

<ParamField body="signalTypes" type="string[]" required>
  Signal types to retrieve.

  Allowed values: `allSignals`, `linkedinActivityIntent`, `newIntentTopic`, `intentScoreIncrease`, `intentScoreDecrease`, `intentTopicRemoved`, `websiteTrafficIncrease`, `websiteTrafficDecrease`, `itSpendIncrease`, `itSpendDecrease`, `surgeInHiring`, `surgeInHiringByDepartment`, `surgeInHiringByLocation`, `headcountIncrease1m`, `headcountDecrease1m`, `headcountIncrease3m`, `headcountDecrease3m`, `headcountIncrease6m`, `headcountDecrease6m`, `headcountIncrease12m`, `headcountDecrease12m`, `riskNews`, `commercialActivityNews`, `corporateStrategyNews`, `financialEventsNews`, `peopleNews`, `marketIntelligenceNews`, `productActivityNews`

  Use `allSignals` to retrieve every available company signal type in one call, except the four intent types (`newIntentTopic`, `intentScoreIncrease`, `intentScoreDecrease`, `intentTopicRemoved`) - name those explicitly.
</ParamField>

<ParamField body="startDate" type="string">
  Limit results to signals detected on or after this date, in `YYYY-MM-DD` format.

  Example: `"2025-01-01"`
</ParamField>

<ParamField body="maxResultsPerSignal" type="integer">
  Maximum number of signal instances to return per signal type per company. Range: `1`–`100`.

  Example: `10`
</ParamField>

<ParamField body="filters" type="object">
  Narrows intent results. Other signal types are unaffected.

  <Expandable title="properties">
    <ParamField body="filters.include.intentTopics" type="string[]">
      Narrows the four intent types to these topics. Use exact names from [Get Company Signal Filter Values](/api-reference/signals/company-signal-filter-values) with `filterType=intentTopics` - a topic that isn't in the catalog returns `400 INVALID_FILTER_VALUE`. Omit to return all topics, up to `maxResultsPerSignal`.

      Example: `["Cloud HR Platform", "Air Cargo"]`
    </ParamField>
    <ParamField body="filters.include.intentCategories" type="string[]">
      Narrows `linkedinActivityIntent` and the four intent types to these categories. See `filterType=intentCategories` for valid values.
    </ParamField>
  </Expandable>
</ParamField>

## Example request

<CodeGroup>

```bash cURL
curl --request POST \
  --url https://api.lusha.com/v3/companies/signals \
  --header 'api_key: YOUR_API_KEY' \
  --header 'Content-Type: application/json' \
  --data '{
    "ids": ["16303253"],
    "signalTypes": ["allSignals"],
    "startDate": "2025-01-01",
    "maxResultsPerSignal": 10
  }'
```

```json Request body
{
  "ids": ["16303253"],
  "signalTypes": ["allSignals"],
  "startDate": "2025-01-01",
  "maxResultsPerSignal": 10
}
```

</CodeGroup>

## Response

### 200 - Success

<ResponseField name="results" type="object[]">
  One entry per requested company ID.

  <Expandable title="properties">
    <ResponseField name="id" type="string">
      The Lusha company ID this entry corresponds to. Example: `"16303253"`
    </ResponseField>
    <ResponseField name="companyName" type="string">
      Company name. Example: `"Lusha"`
    </ResponseField>
    <ResponseField name="domain" type="string">
      Company domain. Example: `"lusha.com"`
    </ResponseField>
  </Expandable>

  <Info>
    Beyond `id`, `companyName`, and `domain`, each result also carries one array per signal type that matched - keyed by the `signalTypes` value you requested (for example `surgeInHiring`, `financialEventsNews`), the same keying pattern the [contact signals](/api-reference/signals/contact-signals) response uses for `promotion` and `companyChange`.
  </Info>

  <Expandable title="intent signal properties">
    Each item under `newIntentTopic`, `intentScoreIncrease`, `intentScoreDecrease`, or `intentTopicRemoved`:

    <ResponseField name="id" type="string">Signal ID. Example: `"2139910966"`</ResponseField>
    <ResponseField name="signalDate" type="string">Week the change was detected. Example: `"2026-09-28"`</ResponseField>
    <ResponseField name="topic" type="string">Intent topic. Example: `"Air Cargo"`</ResponseField>
    <ResponseField name="category" type="string">Category the topic belongs to. Example: `"Other"`</ResponseField>
    <ResponseField name="score" type="integer | null">Current score, 0-100. A high score means the company is researching the topic more than usual. `null` for `intentTopicRemoved`.</ResponseField>
    <ResponseField name="previousScore" type="integer | null">Score the previous week. `null` for `newIntentTopic` and `intentTopicRemoved`.</ResponseField>
    <ResponseField name="changeRatePercent" type="number | null">Week-over-week change as a percentage, negative for a decrease. `null` for `newIntentTopic` and `intentTopicRemoved`.</ResponseField>
  </Expandable>

  <Info>
    A company ID that can't be found returns `id` plus an `error` object (`{ "code": "NOT_FOUND", "message": "Company not found" }`) instead of signal data.
  </Info>
</ResponseField>

<ResponseField name="startDate" type="string">
  The start date used for this request.
</ResponseField>

<ResponseField name="endDate" type="string">
  The end date used for this request (the request date, unless you're querying historical data).
</ResponseField>

<ResponseField name="billing" type="object">
  Credit usage summary for this request.

  <Expandable title="properties">
    <ResponseField name="creditsCharged" type="integer">Credits charged for this request. Example: `3`</ResponseField>
    <ResponseField name="resultsReturned" type="integer">Number of results returned. Example: `1`</ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="tableWrite" type="object">
  Present only when you pass `tableId` on the request. Summarizes what was written to the table. The rest of the response is unaffected even if the table write fails.

  <Expandable title="properties">
    <ResponseField name="tableId" type="string">The table that was written to. Example: `482910`</ResponseField>
    <ResponseField name="added" type="integer">New entities added to the table by this call.</ResponseField>
    <ResponseField name="alreadyPresent" type="integer">Entities from this call that were already in the table.</ResponseField>
    <ResponseField name="columnsCreated" type="integer">Columns auto-created by this call, for example a Signals column created on first use.</ResponseField>
    <ResponseField name="rowsProcessed" type="integer">Rows the column run touched as part of this call.</ResponseField>
    <ResponseField name="rowsCharged" type="integer">Rows that incurred a credit charge.</ResponseField>
    <ResponseField name="rowsAlreadyPaidInTable" type="integer">Rows already paid for in this table, which were not charged again.</ResponseField>
    <ResponseField name="creditsCharged" type="integer">Credits charged for this table write.</ResponseField>
  </Expandable>
</ResponseField>

<Info>
  **Billing:** Charged per matched signal per result via the `showSignalsCompany` action.
</Info>

## Error codes

| Status | Meaning |
|--------|---------|
| `400` | Bad request - invalid input data, or `INVALID_FILTER_VALUE` when an `intentTopics` value isn't in the catalog. |
| `401` | Unauthorized - your API key is missing or invalid. |
| `402` | Payment required - insufficient credits. |
| `403` | Forbidden - account inactive or V3 access not enabled. |
| `429` | Too many requests - you have exceeded the rate limit. |
