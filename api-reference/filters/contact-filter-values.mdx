Returns the valid values for one contact filter type. Call [Contact Filter Types](/api-reference/filters/contact-filter-types) first if you don't already know which `filterType` values are available.

| Filter type | Query required? | Maps to (in [Prospecting Contacts](/api-reference/prospecting/prospecting-contacts)) |
|---|---|---|
| `departments` | No | `filters.contacts.include.departments` |
| `seniority` | No | `filters.contacts.include.seniorityIds` |
| `existingDataPoints` | No | `filters.contacts.include.existingDataPoints` |
| `countries` | No | `filters.contacts.include.countries` |
| `locations` | Yes (2–256 chars) | `filters.contacts.include.locations` |

## Endpoint

```
GET https://api.lusha.com/v3/contacts/prospecting/filters/{filterType}
```

## Authentication

<ParamField header="api_key" type="string" required>
  Your Lusha API key.
</ParamField>

## Path parameters

<ParamField path="filterType" type="string" required>
  The filter type to fetch values for.

  Allowed values: `departments`, `seniority`, `existingDataPoints`, `countries`, `locations`
</ParamField>

## Query parameters

<ParamField query="query" type="string">
  Search term to filter the returned values. Required for `locations` (2–256 characters); optional and ignored for filter types that don't require a query.
</ParamField>

## Response

<ResponseField name="values" type="any">
  The valid values for the requested `filterType`. The shape depends on which filter type you requested:

  - **`departments`** — an array of department name strings, for example `["Sales", "Engineering"]`
  - **`existingDataPoints`** — an array of data point strings, for example `["work_email", "work_phone"]`
  - **`countries`** — an array of country code strings, for example `["US", "CA"]`
  - **`seniority`** — an array of `{ id, name }` objects; pass the `id` values in `seniorityIds`
  - **`locations`** — an array of location objects with `city`, `state`, `country`, `continent`, and `countryGrouping`, matching the shape used in search requests

  <Info>
    The OpenAPI schema declares `values` as an open-ended field since its shape varies by filter type. Treat the examples above as representative, not a fixed contract.
  </Info>
</ResponseField>

## Error codes

| Status | Meaning |
|--------|---------|
| `400` | Bad request — invalid `filterType`, or missing/too-short `query` for a filter type that requires one |
| `401` | Unauthorized — invalid or missing API key |
| `403` | Forbidden — account inactive or V3 access not enabled |
| `429` | Too many requests — rate limit exceeded |

## Examples

<CodeGroup>

```bash Filter type without a query (seniority)
curl --request GET \
  --url https://api.lusha.com/v3/contacts/prospecting/filters/seniority \
  --header 'api_key: YOUR_API_KEY'
```

```bash Filter type with a query (locations)
curl --request GET \
  --url 'https://api.lusha.com/v3/contacts/prospecting/filters/locations?query=San%20Francisco' \
  --header 'api_key: YOUR_API_KEY'
```

</CodeGroup>

```json Example response — seniority
{
  "values": [
    { "id": 4, "name": "Director" },
    { "id": 5, "name": "VP" }
  ]
}
```

```json Example response — locations
{
  "values": [
    {
      "city": "San Francisco",
      "state": "California",
      "country": "United States",
      "continent": "North America",
      "countryGrouping": "AMER"
    }
  ]
}
```

<Tip>
  Filter types with `requiresQuery: false` (`departments`, `seniority`, `existingDataPoints`, `countries`) rarely change — cache their values instead of calling this endpoint before every search.
</Tip>
