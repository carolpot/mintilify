---
title: "Contact email fields"
description: "Email address objects, types (work/private), confidence scores, and update dates."
---

Email data is returned on the contact record as an array of email address objects, and via the deprecated flat `emails` array kept for backwards compatibility.

## `emailAddresses` (recommended)

Each entry in `emailAddresses` is an object with the following fields.

| Field | Type | Description |
|---|---|---|
| `address` | string | The email address. Some endpoints return this as `email` instead — both names carry the same value. |
| `emailType` | string | The type of email address. One of `work` or `private`. Some endpoints return this as `type` instead. |
| `emailConfidence` | string | A confidence grade for the address, for example `A+`. Higher grades indicate Lusha has greater confidence the address is valid and deliverable. Lusha doesn't publish a full breakdown of the grade scale. |
| `updateDate` | string | The date this email address was last verified, in `YYYY-MM-DD` format. |

```json
{
  "emailAddresses": [
    {
      "address": "dustin@lusha.com",
      "emailType": "work",
      "emailConfidence": "A+",
      "updateDate": "2024-01-15"
    }
  ]
}
```

## `emails` (deprecated)

`emails` is a plain array of email address strings with no type, confidence, or update date. Use `emailAddresses` for new integrations — see [Deprecated fields](/data-catalog/overview#deprecated-fields).

```json
{
  "emails": ["dustin@lusha.com"]
}
```

<Tip>
  When calling contact enrichment endpoints, use `filterBy: "emailAddresses"` (or the equivalent `metadata.filterBy` in bulk requests) to return only contacts that have at least one email address.
</Tip>
